> **版本性质**：预发布修复版（发奖回调数据缺陷修复）
> **发布日期**：2026-08-31
> **Git Tag**：`1.0.1-alpha.3`（二进制分发仓库 javaice007/flame_sdk_ios）
> **前一版本**：1.0.1-alpha.2（静态双线结构定型；本版产物结构与依赖完全不变，仅胶水层逻辑修复）

## 修复的问题

### 1. TK 线：发奖回调 `transId` 恒为空（客户反馈，真机复现确认）

**现象**：`onAdReward:userCustomData:transId:` 回调中 `transId` 恒为 `@""`，服务端发奖
对账功能受损。验证工程真机实测（iPhone 16 Pro / iOS 26.6，分支
`verify/tk-alpha2-reward-callback`）：看完完整激励视频，`transId=` 仍为空。

**根因**（依据验证方对 1.0.1-alpha.2 产物的反汇编报告）：
`AtRewardAdapter.m` 发奖回调从 `self.localExtra` 回读三个字段，其中
`localExtra[@"transId"]` 这个 key 在整个 SDK 中**只被读取、从未被写入**
（仅有的两处 `setObject:forKeyedSubscript:` 是 userId / userCustomData），
TopOn 发奖回调自带的 `extra` 参数也未被读取 → transId 对任何广告源恒为空。

**修复**（`adapter/tk/AtRewardAdapter.m` 发奖回调）：
1. 优先读取 TopOn 发奖 `extra` 中的三方交易号
   `extra[kATTrackerExtraNetworkTransIDKey]`（= `@"third_trans_id"`，
   AnyThinkSDK `ATAdEnums.h` 字符串宏，无链接期符号依赖）；
2. 取不到时由 Flame 生成唯一事务号兜底（`NSUUID UUIDString`），保证
   transId 恒非空、且连续多次发奖互不相同；
3. `userId` / `userCustomData` 回传行为保持与 1.0.1-alpha.2 一致（传入即回传，
   无参 load 恒空），满足回归基线。

### 2. TB 线：发奖回调 `userCustomData` 恒为空 + `userId`/`transId` 无兜底（SDK 侧排查发现）

**排查结论**（TB 与 TK 不同构，`TbRewardAdapter` 直接读 ToBid 的 `WindMillRewardInfo`）：

| 字段 | 1.0.1-alpha.2 行为 | 判定 |
|---|---|---|
| `transId` | 读 `reward.transId`（WindMillSDK.h 注释"交易的唯一id"），数据源真实 | 大概率非空，但无兜底 |
| `userCustomData` | **硬编码 `@""`**：load 入参只进 `request.options`（ToBid 服务端回传参数），客户端回调不回传 | ❌ 确定缺陷 |
| `userId` | 读 `reward.userId`，依赖 ToBid 服务端回显，无本地兜底 | ⚠️ 与 TK"传入即回传"语义不一致 |

**修复**（`adapter/tb/TbRewardAdapter.m`）：
1. `loadWithUserId:userCustomData:` 时快照入参（`loadedUserId` / `loadedUserCustomData`）；
2. 发奖回调：`userId` = ToBid 回传 ?: load 入参 ?: @""；
   `userCustomData` = load 入参 ?: @""（与 TK 语义对齐，传入即回传）；
   `transId` = `reward.transId` ?: `reward.thirdTransId`（腾讯/百度三方标识）?: Flame UUID 兜底；
3. 附 `[TB_REWARD_DIAG] reward:` 日志，标注 transId 实际来源
   （windmill / thirdTransId / flame-uuid），便于真机回归确认。

### 待真机回归（验证工程，对应验证方报告第五节验收标准）

1. 客户侧仅升级 Pod（TK：`flame_sdk_ios 1.0.1-alpha.3`；TB：`flame_sdk_ios_tb 1.0.1-alpha.3`）；
2. TK 线完整看完一条激励视频，`onAdReward` 日志 `transId=` 非空；
3. 连续两次发奖，两次 transId 均非空且互不相同；`userId`/`userCustomData` 行为与 alpha.2 一致；
4. TB 线同流程：`userCustomData` 传入即回传（alpha.2 及之前恒空）；`userId` 非空；
   `transId` 非空，并观察 `[TB_REWARD_DIAG] reward:` 日志中 `src=` 标注的实际来源
   （windmill 为最优，flame-uuid 为兜底，若大量出现 flame-uuid 需与 ToBid 确认服务端回传）。

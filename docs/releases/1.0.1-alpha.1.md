## 修复的问题（P0：接入即启动闪退）

公开 Pod **1.0.0（TK/TB 双线均受影响）** 通过 CocoaPods 正常集成后，App 在启动瞬间闪退，
应用代码尚未执行，崩溃发生在 dyld 加载阶段，100% 复现：

```text
termination: namespace=DYLD, signal=SIGABRT
symbol not found in flat namespace '_OBJC_CLASS_$__TtC11WindMillSDK11WindMillAds'
```

无法解析的符号共 8 个（均为 ToBid/WindMillSDK 类）：
`WindMillAds` / `WindMillSplashAd` / `WindMillAdRequest` / `WindMillBannerView` /
`WindMillNativeAdView` / `WindMillRewardVideoAd` / `WindMillIntersititialAd` / `WindMillNativeAdsManager`

### 根因

1. 1.0.0 交付的 `flame_sdk_ios.framework` 为**动态库**（MH_DYLIB），同时内置 TK/TB 两线胶水（单二进制）。
2. 构建脚本（`xcFramework_build.sh`）对 ToBid 的 8 个类使用 `-undefined dynamic_lookup`
   扁平命名空间延迟解析：链接期刻意隐藏 ToBid 静态归档、把 WindMill 符号留为未定义，
   指望运行期由宿主 App 解析。
3. `ToBid-iOS-RC` 仅以**静态归档**（伪装成 framework 的 .a）提供，静态链入主程序后符号
   不出现在可被 dyld 扁平查找的导出表中 → 启动即 abort。
4. 客户端无法绕过（导出符号表 `-exported_symbols_list`、`force_load` 均已尝试无效），
   属发布产物缺陷，必须由 SDK 侧修复。

## 修复方案：静态双线产物（release/ios-dual-line）

1.0.1-alpha.1 起两条线均为**静态 framework**（ar 归档，链接进客户主程序），
各自只含本线胶水：

| 产物 | 内容 | 跨平台符号解析 |
|---|---|---|
| `flame_sdk_ios.xcframework`（TK） | Flame core + FlameTKProvider + At*Adapter | AnyThink 符号由 AnyThinkSDK.framework（AnyThinkiOS pod）在 App 链接期解析 |
| `flame_sdk_ios_tb.xcframework`（TB） | Flame core + FlameTBProvider + Tb*Adapter | WindMill 符号由 ToBid-iOS-RC 静态归档在 App 链接期解析 |

关键特性：

- **全部跨平台符号在客户 App 链接期解析**，dyld 阶段无跨库查找，闪退根除。
- **TK 产物零 WindMill 符号引用**（8 个崩溃符号在 TK 产物中不存在）；
  **TB 产物零 AnyThink 符号引用**（TB 客户不接 AnyThinkiOS，链接期也不出现）。
- 客户升级**只改 Podfile 版本号**：module/import/API 全部不变；flame 由动态变为
  链接进主程序（包内不再有 flame 动态 framework）。

|---|---|

## 2. 参数流（create vs load）

- **create**（`FlameSdk.createRewardAdWithViewController:placementId:listener:`）携带：VC、Flame placementId、listener
- **load** 携带 userId / userCustomData：
  - TK：写入 `localExtra[kATAdLoadingExtraUserIDKey]` / `[kATAdLoadingExtraUserDataKeywordKey]` 随 `loadADWithPlacementID:extra:delegate:` 传入
  - TB：`request.userId = userId`；`request.options = @{@"userCustomData": …}`（服务端激励回传参数）

## 3. Callback 兼容矩阵（REWARD_CALLBACK_COMPATIBILITY_MATRIX）

| Flame 方法 | TAKU/TopOn 映射（AtRewardAdapter.m） | TOBID/WindMill 映射（TbRewardAdapter.m） |
|---|---|---|
| onAdLoaded | `didFinishLoadingADWithPlacementID:` | `rewardVideoAdDidLoad:` |
| onAdShow | `rewardedVideoDidStartPlayingForPlacementID:extra:` | `rewardVideoAdDidVisible:` |
| onAdClicked | `rewardedVideoDidClickForPlacementID:extra:` | `rewardVideoAdDidClick:` |
| onAdPlayComplete | `rewardedVideoDidEndPlayingForPlacementID:extra:` | `rewardVideoAdDidPlayFinish:didFailWithError:`(error==nil) |
| onAdReward | `rewardedVideoDidRewardSuccessForPlacemenID:extra:` | `rewardVideoAd:reward:`(WindMillRewardInfo) |
| onAdClosed | `rewardedVideoDidCloseForPlacementID:rewarded:extra:` | `rewardVideoAdDidClose:` |
| onAdError | `didFailToLoadADWithPlacementID:error:` / `rewardedVideoDidFailToPlay…error:` | `rewardVideoAdDidLoad:didFailWithError:` / `rewardVideoAdDidShowFailed:error:` / `didPlayFinish`(error!=nil) |
| （未映射的三方回调） | — | `didClickSkip:`（空实现）、`willVisible/willClose`（仅日志）、`didAutoLoad…`（空实现） |

**参数保真度差异**：
- onAdReward 的 `transId`：TK 恒 `@""`（读 `localExtra[@"transId"]`，该 key 全工程无写入）；**TB 有效**（WindMillRewardInfo.transId）
- onAdReward 的 `userCustomData`：TK 回读 localExtra（有值）；**TB 恒 `@""`**（reward 对象无此字段回传）
- onAdReward 的 `userId`：TK 回读 localExtra；TB 来自 reward.userId

## 4. onAdReward 的真实语义（REWARD_VERIFY_PUBLIC_SEMANTICS）

**= CLIENT_PLATFORM_CALLBACK_ONLY：`onAdReward` 仅代表聚合平台 SDK 在客户端回调了"奖励发放"。**

- TK：AnyThink `didRewardSuccess`（AnyThink 内部是否完成服务端校验对 Flame 不透明）
- TB：WindMill `reward:` 回调，附带 transId 可供宿主自行做服务端对账
- **Flame 自身无服务端 reward verify API、无验签、无 transId 校验**。不得把 onAdReward 表述为"服务端验签成功"。

## 5. 回调顺序

基于 Adapter 映射的典型顺序（三方 SDK 实际派发顺序决定）：

- TK：didStartPlaying(onAdShow) → [didClick] → didEndPlaying(onAdPlayComplete) → didRewardSuccess(onAdReward) → didClose(onAdClosed)
- TB：didVisible(onAdShow) → [didClick] → didPlayFinish(onAdPlayComplete) → reward:(onAdReward) → didClose(onAdClosed)

**ORDER_NOT_GUARANTEED**：Flame 层不重排、不补发、不保证相对顺序（如 reward 与 complete 的先后由三方决定）。skip 场景（TK）close 的 `rewarded:NO` 与（TB）`didClickSkip` 均不影响回调序列，宿主无法从 Public API 感知 skip。

## 6. 重复回调防护

**三层均无 reward 防重**：
- `FlameRewardAdImpl`：无
- `AtRewardAdapter` / `TbRewardAdapter`：无（仅直接 respondsToSelector 转发）
- 无 Listener Wrapper
- 对比：**init 链路**有 hasCalled 防重（UpdateAppCallback/AdapterInitCallback）；TB **Splash** 有 finishOnce 幂等；Reward 无
- Demo 侧：init 结果做了 didNotify 防重；reward 未防

## 7. 生命周期事实（AD_LIFECYCLE）

- 粒度：每次 `createRewardAd…` 新建 `FlameRewardAdImpl + Adapter` 实例；**Flame 层无缓存池/单例广告对象**
- TK：广告实体缓存在 AnyThink 内部（placementId 级）；adapter 无状态，isReady/isLoading 查询 `ATAdManager` 全局
- TB：adapter **强持有** `WindMillRewardVideoAd`；WindMill 的 delegate 属性为 `weak`（WindMillSDK.h:2274）→ **无 retain cycle**；重新 load 会先置空旧对象 delegate（防 stale delegate）
- adapter 对 listener / viewController 均 **weak**：宿主释放 listener 即静默断连
- close→reload：TB 已修复（show 时动态取顶层 VC，`flame_topViewController()`，防 load 期缓存 VC 失效；commit 1abfdae）
- 防护矩阵：重复 load（TK✅ 查 AnyThink 状态 / **TB✗ isLoading 恒 NO**）；重复 show（✅ isReady 前置）；多次 reward（✗ 无守卫）；timeout（✗ Reward 无，仅 Splash 有 5s）；cancel（✗ 无广告级取消）

## 8. 语义缺口汇总（影响 Public API 语义的事实）

| 缺口 | 位置 | 对契约的影响 |
|---|---|---|
| TK transId 恒空串 | AtRewardAdapter.m:136 | 宿主在 TK 线不能依赖 transId 做对账 |
| TB userCustomData 恒空串 | TbRewardAdapter.m:225 | 宿主在 TB 线 onAdReward 拿不回自定义数据 |
| skip 不可感知 | TbRewardAdapter.m:203 空实现；AtRewardAdapter.m:142 `rewarded:` 被忽略 | close 后无法区分"看完关闭/跳过关闭" |
| 无 reward verify | 全局 | onAdReward 只是客户端事件 |
| 无 eCPM | 全局（ECPM_PUBLIC_API=NONE / ECPM_INTERNAL_API=NONE） | 变现数据不经过 Flame |
| TB isLoading 恒 NO | TbRewardAdapter.m:107-110 | 公共 isReady/isLoading 语义在两线不一致 |

# 03 · 网络签名与加密

> 代码证据：`flame_sdk_ios/utils/FlameNetworkUtils.m`、`FlameMd5SignatureUtils.m`、`FlameAesCryptoUtils.m`、`core/FlameConfigManager.m`

## 网络层

- 唯一后端调用：`POST https://api.adsurge.cn/api/v1/sdk/init`
- Client：`[NSURLSession sharedSession]`；timeout **15s**；无 retry；无自定义 header（无 UA/设备参数）
- completion 一律 `dispatch_async(main_queue)`；completion block 显式 copy
- 请求去重三板斧（FlameConfigManager）：
  1. `currentTask` 可取消（clearCache / 新请求前）
  2. `requestGeneration` 代际计数——旧请求 completion 到达时 generation 不匹配则丢弃
  3. `activeCallback` 属性强持有回调对象，completion 内锁内原子提取置 nil（防野指针/防 clear 竞态）
- 死代码：`doPost:`（form-urlencoded 版本）无调用方

## 请求签名（FlameMd5SignatureUtils）

1. 参与签名的业务参数：`{appId, version, timestamp(ms)}`（FlameConfigManager.m:141-144）
2. key 字典序升序 → `k1=v1&k2=v2...` 拼接
3. 追加盐：`...&key=<appKey>`
4. **MD5**，输出小写 hex（CommonCrypto `CC_MD5`）
5. sign 加入 JSON body

限制（事实）：MD5 抗碰撞性弱；**无 nonce** → 请求可重放；timestamp 是唯一时效参数。

## 响应解密（FlameAesCryptoUtils，OpenSSL EVP）

- `edata` = Base64( `IV(12B)` + `Ciphertext` + `TAG(16B)` )
- AES-128/192/256-GCM 按 **appKey 的 UTF-8 字节长度**（16/24/32）自动选择；**无 KDF**，appKey 即对称密钥
- 解密流程：分离 IV/CT/TAG → EVP_DecryptInit → DecryptUpdate → SET_TAG → DecryptFinal 校验（失败返回 nil → init fail "-1"）
- 加密方向（`encrypt:rawKey:`）同样实现（当前 SDK 运行时仅用解密路径）
- OpenSSL 依赖：二进制 `@rpath/OpenSSL.framework`（podspec 透传 OpenSSL-Universal ~>3.6）

## 密钥与敏感信息现状

| 项 | 现状 |
|---|---|
| platformAppkey 传入 | 客户代码明文传入 `initWithAppId:appKey:` |
| aKey（平台凭证）落盘 | **UserDefaults 明文**（suite `flame_sdk_conf`，FlameConfigLocalStorage.m） |
| Keychain | 未使用 |
| 日志脱敏 | 无（日志不含 appKey 明文；`FlameAppEntity.description` 会拼接 aKey，存在被 %@ 打印泄漏的路径） |
| 证书校验/pinning | 无（系统默认） |

> Secret Gate：本文档只记录参数名与机制，不记录任何真实密钥值。

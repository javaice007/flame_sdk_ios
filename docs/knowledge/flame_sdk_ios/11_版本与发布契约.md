## 2. VERSION_SOURCE_OF_TRUTH 判定

**VERSION_SOURCE_OF_TRUTH = Podspec s.version + binary 分发仓库 Git Tag（二者由 `s.source = {git, tag => s.version.to_s}` 机械绑定，人工保证相等）**

依据（真实发布 commit d708b7b 的 message）：
- "Version: 1.0.0 (TK = TB, official stable release)"
- "Git Tag: 1.0.0 (created in binary distribution repo)"
- 发布 commit 明确列出改动：双 podspec 版本、docs/releases 快照、README、changelog

派生/需人工同步项：
- `FLAME_SDK_VERSION`（FlameConfigManager.m:17）——**必须与 podspec 同步手改**（getVersion 与后端请求 version 都来自它）
- MARKETING_VERSION/CFBundleShortVersionString —— **长期漏改的漂移项**（"1.0"），属历史遗留，不影响 pod install（CocoaPods 用 podspec 版本），但宿主在"framework 关于页"看到的是 1.0

不存在单一自动化的版本注入机制（无 agvtool/CI 注入），故严格说是"**双 Anchor + 一处手工镜像**"结构，不是 INCONSISTENT（发布语义上 podspec/tag 一致），但有三处已知漂移面。

## 3. 版本进入后端请求的真实链路

```
FlameSdk（init 触发）
→ FlameConfigManager.updateAppWithAppId:appKey:callback:
→ params[@"version"] = FLAME_SDK_VERSION        // FlameConfigManager.m:143
   （FLAME_SDK_VERSION = @"1.0.0" 静态字符串常量，FlameConfigManager.m:17）
→ sign 覆盖 {appId, version, timestamp} → POST body
```

结论：**BACKEND_REQUEST_VERSION_SOURCE = 源码硬编码常量 FLAME_SDK_VERSION**（不是 getVersion 调用、不是 Bundle/podspec/宏；getVersion 与请求 version 恰好同源于此常量）。

## 4. 一次正式发布的真实时序（VERSION_RELEASE_FLOW）

依据 d708b7b/55c6288 两个 release commit + 文档：

```
1. 改版本（人工、多处）：
   a. flame_sdk_ios.podspec        s.version
   b. flame_sdk_ios_tb.podspec     s.version（必须与 a 相等）
   c. flame_sdk_ios/core/FlameConfigManager.m  FLAME_SDK_VERSION（getVersion + 后端请求）
   （MARKETING_VERSION 历史上漏改 → plist 漂移 1.0）
2. ./xcFramework_build.sh          → build/flame_sdk_ios.xcframework
3. 人工同步 xcframework 到 GitHub binary repo（javaice007/flame_sdk_ios）根目录
4. 在 binary repo 打 tag = 版本号（如 1.0.0）
5. podspec 推送到私有 spec repo（javaice007/flame-specs，pod repo push）
6. dev 仓库：release commit（版本说明写入 commit message）+ docs/releases/<ver>.md 快照 + README 推荐 version
7. 客户：source flame-specs 后 pod 'flame_sdk_ios' / 'flame_sdk_ios_tb', '<ver>'
```

需要手工同时维护的位置清单：podspec ×2、FLAME_SDK_VERSION、README、docs/releases、（应改而未改的 MARKETING_VERSION）。无 preflight 脚本实际存在（README 引用的 scripts/preflight_release.sh 不在仓库）。

## 5. 发布规范（README 记录）

- alpha 版本号格式必须带序号（1.0.0-alpha.1/2/3…），禁止裸 alpha、跳号、覆盖、重复发布
- 两个 pod 互斥、版本号始终一致（TK = TB）
- 版本快照必须落 docs/releases/<version>.md
